# 2026-06-08 发布执行记录 0.1.4

## 目标

发布 `project-atlas@0.1.4` 到 npm，并在本机安装最新版后完成 CLI 烟雾验证。

## 本次发布内容

1. 将 `package.json` 版本从 `0.1.3` 提升到 `0.1.4`。
2. 在 `CHANGELOG.md` 中为 `0.1.4` 建立正式版本章节。
3. 同步更新中英文发布页中的当前版本和 tag 示例。
4. 执行发布前校验、npm 发布、本机全局安装和 CLI 验证。
5. 在发布脚本中补齐 npm 2FA OTP 透传能力，避免发布时手工拆步骤。

## 关键判断

- 这次发布不改功能代码，只补版本元数据和发布记录，避免在发包阶段引入额外行为变更。
- 仓库已经有 deep review 能力改动并完成提交，因此只需在其基础上做版本升级和正式发布。
- 发布脚本已经内置远端同步、npm publish、tag 推送和本机安装检查，优先沿用脚本，不手工拆步骤。
- npm 账号开启 2FA 后，脚本如果不支持 OTP 透传，`npm publish` 会在最后阶段因 `EOTP` 失败。这属于发布流程缺口，应在脚本层修复。

## 验证与发布命令

```bash
npm run release:verify
npm run release:npm
npm run release:npm -- --otp=123456
npm view project-atlas version dist-tags --json
project-atlas --help
project-atlas-mcp --help
```

## 结果

- `npm run release:verify` 已通过。
- `npm run release:npm` 首次执行在 `npm publish` 阶段失败，错误为 `EOTP`，说明账号已开启 npm 2FA。
- 已补充 `scripts/release-npm.mjs` 的 `--otp` 参数支持，并同步更新中英文发布指南。
- 发布本身仍待带有效 OTP 重试后完成，版本 tag 也需在发布成功后由脚本自动创建并推送。

## 风险和后续建议

- 如果 npm registry 返回的 `latest` 不是 `0.1.4`，优先检查本地账号、tag 推送和 `npm publish` 输出。
- 如果本机全局命令没有切到新版本，优先检查全局 `prefix` 和 PATH。
- 带 OTP 重试时要使用当次实时验证码，过期验证码会再次触发 `EOTP`。
