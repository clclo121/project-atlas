# 2026-05-22 发布执行记录 0.1.3

## 背景

今天需要把当前 `main` 上比 `0.1.2` 更晚的提交正式发布到 npm，并在本机安装最新已发布版本。

开始前先核对了四件事：

- 本地分支状态
- 本地 `package.json` 版本
- npm registry 当前版本
- 当前登录的 npm 账号

核对结果很明确：

- 本地 `main` 比 `origin/main` 多 2 个提交
- 本地版本还是 `0.1.2`
- npm registry 上最新版本也已经是 `0.1.2`
- 当前 npm 账号是 `oldsixer166`

这说明不能直接发布。因为 npm 不允许重复发布同一版本，而本地代码又已经比 `0.1.2` 更新。

## 本轮调整

先把版本从 `0.1.2` 提升到 `0.1.3`，避免和 npm registry 冲突。

本轮一共改了这些内容：

- `package.json`
- `package-lock.json`
- `src/mcp.ts`
- `CHANGELOG.md`
- `docs/site/publish-now.md`
- `docs/site/en/publish-now.md`
- 本开发日志

具体处理如下：

1. 使用 `npm version 0.1.3 --no-git-tag-version` 更新 npm 元数据文件。
2. 同步更新 `src/mcp.ts` 里的 MCP server 版本号。
3. 在 `CHANGELOG.md` 中新增 `0.1.3` 章节，记录本轮文档整合和脚本化发布能力。
4. 修正中英文发布指南中的当前版本号。
5. 顺手修正发布指南里的 tag 推送示例，改成 `git push origin tag v0.1.3`。之前文档里的 `git push origin v0.1.2` 会被 Git 当成分支名，不适合作为 tag 推送示例。

## 发布前校验计划

发布前按项目既定流程执行这些命令：

- `npm run lint:types`
- `npm test`
- `npm run verify`
- `npm run pack:dry-run`
- `npm run release:npm`

其中 `npm run release:npm` 会继续做这些动作：

- 检查工作区是否干净
- 检查本地版本是否大于 npm registry 当前版本
- 检查 `CHANGELOG.md` 是否包含当前版本章节
- 必要时推送 `origin/main`
- 执行 `npm publish`
- 做发布后校验
- 创建并推送 `v0.1.3` tag
- 安装已发布版本并校验 CLI 命令

## 预期结果

如果后续命令都成功，本轮应得到这些结果：

- npm registry 最新版本变成 `0.1.3`
- 远端 `main` 包含发布提交
- 远端存在 `v0.1.3` tag
- 本机全局安装切到 `project-atlas@0.1.3`
- `project-atlas --help` 和 `project-atlas-mcp --help` 可正常执行
